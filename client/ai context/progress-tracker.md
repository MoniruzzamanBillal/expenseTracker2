## Current state

Core screens are built and working: home, add-transaction, history, monthly+weekly (merged into one tab with an in-page segmented control, spec 06 Decision 8), smart-add (AI-assisted entry, reached via a button on Add Transaction rather than its own tab, spec 06 Decision 7), auth/register. The app now has a custom `theme/` design-system (colors/typography/spacing, light+dark) replacing bare `react-native-paper` defaults — `architecture.md`/`code-standards.md`/`project-overview.md` have been updated to reflect this. There is no active multi-phase build plan — this is a maintained, already-shipped personal project, not greenfield work. The `specs/` scaffolding below exists for the _next_ piece of nontrivial work, not a backlog of already-completed phases.

As of 2026-09-14, specs 12–18 (categories, category-on-transaction wiring, a new 5th Settings tab with profile editing, budgets, receipt photo attachment, trend charts) are implemented client-side against the already-shipped server modules — see each spec's row below for what it added and the two implementation-fix specs (19, 20) for where the client deviated from a spec's literal text to match the real server contract. None of the six were manually verified in a running app this session (no dev server/browser/device available) — `yarn lint`/`npx tsc --noEmit` are clean for all of them, but a human pass against a live server is still needed before treating this batch as fully done, same standing caveat as spec 10's checklist.

As of 2026-09-16, specs 21–24 (Home category breakdown, Smart Add category picker, Trend months picker, and three small type-drift fixes) are implemented — ported from a reference implementation (`Expense tracker app redesign/uploads/client`, a prior working snapshot of this app) after verifying each assumed server contract still holds against the live `server/` code (all four did, no server changes needed). `yarn lint`/`npx tsc --noEmit` clean; not yet manually verified in a running app.

- [ ] FETCH-1 — axios interceptor never rejects on HTTP errors. Still open and still global; spec 28 did **not** change the interceptor, it added an opt-in `apiPostOutcome`/`usePostOutcome` so the three save paths can tell a server rejection from a dead network without it. Spec 35 (2026-10-05) extended the same opt-in to the PUT leg (`apiPutOutcome`/`usePutOutcome`) for both receipt-upload surfaces, again without touching the interceptor. Every write path that needs to distinguish a rejection from a dead network now has an escape hatch; the interceptor itself is still the real fix.

- [x] AUTH-2 — 401 handling doesn't sync in-memory session state — resolved by `specs/39-access-refresh-token-auth.md` (2026-10-11) via spec 25's bridge module. `axiosInstance.ts` now holds no storage or state code of its own; a forced logout goes through `UserProvider`'s `logoutFunction`, the same one Settings' button uses, which clears storage **and** `user`/`accessToken`/`refreshToken` together.
