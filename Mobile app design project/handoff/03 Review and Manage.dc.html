Screen 4 · app/(tabs)/monthlyTransactions.tsx

Activity · month + week

Period net on top, a day-by-day spend strip to scan the shape of the month, then the day-grouped list. The accordion is gone — every day is open, headed by its own in/out.

Month GET /transactions/monthly-transaction?targetMonth=N → {income, expense, transactionData[{date, income, expense, transactions}], categoryBreakdown}. Strip = expense per date, days missing from transactionData drawn as empty ticks.
Avg out/day expense ÷ days elapsed (spec 01's existing calc).
Stepper targetMonth only — the server pins the year to the current UTC year, so the stepper stops at January and at the current month.
Week GET /transactions/weekly-transaction → weekStart…weekEnd (exclusive; show weekEnd − 1 day). No parameter, so no week stepper. transactionData isn't server-sorted — sort by date desc client-side.
Chips categoryBreakdown → client-side filter of the list (existing behaviour).

Screens 5 + 6 · app/(tabs)/history.tsx

Insights · year + trend

History becomes Insights, with Trend as its second segment (it was a hidden tab inside Monthly). Year answers "how did this year go"; Trend answers "am I spending more lately".

Year GET /transactions/yearly-transaction?targetYear=YYYY → {totalIncome, totalExpense, yearSummary[{month 0–11, income, expense, transactionCount}]}. Rows use transactionCount.
Drill-in Free only for the current year: row → Activity with targetMonth = month+1. Past years show no chevron because the monthly endpoint can't take a year.
Trend GET /transactions/trend-transaction?months=3|6|12|24 → monthlySummary[{targetMonth "YYYY-MM", income, expense}] oldest→newest; categoryBreakdown = latest month's expenses only.
Charts gifted-charts BarChart (grouped, Year) and LineChart with areaChart on expense (Trend); PieChart donut for the split. Income/expense series use pos/neg; category slices use the ramp.

Screen 7 · app/(tabs)/budgets.tsx

Budgets

Sorted by how close each one is to its limit, so the rows that need attention are on top. Tone does the talking: danger when over, warning from 80%, accent otherwise.

Feed GET /budgets → [{_id, categoryId, category{name, icon}, monthlyLimit, spent, percentage, isOverLimit}] — spent is this month's expense per category, server-computed.
Tone isOverLimit → neg · percentage ≥ 80 → warn (client threshold) · else accent. Bar width min(percentage, 100)%.
Summary Σspent / ΣmonthlyLimit across budgets (client).
Create / edit POST /budgets {categoryId, monthlyLimit}; PATCH /budgets/:id {monthlyLimit}; DELETE /budgets/:id (hard delete). Category locked when editing. 409 → "A budget already exists…" toast.
Diverged Promoted to a tab. Sheet shows "spent this month" for the picked category from the cached monthly categoryBreakdown.

Screen 8 · app/(tabs)/transaction-requests.tsx

Requests inbox

An inbox, not a list: each card says where it came from and when it happened, and offers two moves. Reject is quiet; Review opens the accept sheet.

Feed GET /transaction-requests → pending only, createdAt desc. Card: sourceApp · sourceType (fuel → gas-station, maintenance → tools, accessory → tag-outline), occurredAt, title, amount, description.
Accept PATCH /transaction-requests/:id/accept {title?, description?, amount?} — the server always creates an uncategorized expense. The picked category is applied with a follow-up PATCH /transactions/update-transaction/:transaction._id {categoryId}.
Reject PATCH /:id/reject — card leaves with a 5 s "Rejected" toast (no undo endpoint, so no undo button).
Date The new transaction's date is acceptance time (createdAt), not occurredAt. The sheet says so.

Screen 9 · app/(tabs)/settings.tsx

Settings

Profile, appearance, categories, sign out — in that order, one card each. Categories are the only list that grows, so they get the room.

Profile GET /auth/me → name, email, profilePicture. PATCH /auth/update-profile accepts name only — email is shown read-only and there's no photo action (see backend gaps).
Categories GET /categories (createdAt asc); POST {name, icon}; PATCH /:id {name?, icon?}; PATCH /:id/delete (soft). 409 → "A category with this name already exists".
Icons category.icon stores MaterialCommunityIcons names (CATEGORY_ICON_OPTIONS, 27). Kept as MCI so existing data renders; everything else is Ionicons.
Appearance Today ThemeProvider follows the OS only. The segmented control needs a stored preference (AsyncStorage) — client-only, no API.
